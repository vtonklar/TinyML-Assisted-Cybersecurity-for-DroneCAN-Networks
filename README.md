# TinyML-Assisted Cybersecurity for DroneCAN Networks

Senior project, Department of Computer Engineering, Faculty of Engineering,
King Mongkut's University of Technology Thonburi (KMUTT).

A **two-tier store-and-forward CAN bridge** that protects a DroneCAN/UAVCAN
sensor bus:

- **Tier 1 (deterministic rules)** — identifier allowlist, DLC check, per-ID
  rate limit. Stops identity and cadence violations per frame, and forwards
  only accepted traffic to the trusted segment.
- **Tier 2 (TinyML)** — a Random Forest (50 trees, depth 8, **72 KB**) over
  **24 temporal/physics features of 100 ms traffic windows**. Catches what
  rules provably cannot: a masquerading node that sends a plausible but
  physically impossible value with a valid ID at a valid cadence.

Everything is developed and measured on a reproducible virtual CAN lab
(Linux SocketCAN `vcan`); the same pipeline validates on ARM (Raspberry Pi,
Arch Linux ARM) and ports to the STM32 flight stack as quantized C with
golden-test verdict equivalence.

## Measured results (one command, real pipeline)

`12_defense_demo.py` replays the full 8-scenario storyline through the real
bridge code — nothing is a mock verdict (see `docs/results_poc.txt`):

| Scenario | Tier | Measured result | Latency |
|---|---|---|---|
| Benign (30 s honest) | — | **0 false alarms** / 299 windows | — |
| Injection (rogue ID) | 1 | 20/20 frames dropped (allowlist) | per frame |
| Flood at 1 kHz | 1 | 1000/1000 spam dropped (+49 honest lost) | per frame |
| Masquerade +500 m | 2 | 33/34 windows alerted | ~27 ms |
| Slow drift +2 m/s | 2 | 34/34 windows alerted | ~49 ms |
| Shadow node | 2 | 34/34 windows alerted (**unseen class**) | ~104 ms |
| Replay (20 s old) | 2 | 2/34 windows (seams only — named ceiling) | seam only |
| OTA trojan (−2 m/s sink) | 1+2 | trigger 1/1 dropped; sink 36/44 windows | ~110 ms |

Rows 5–7 are attack classes **unseen in training** — those rows measure
generalization, not memorization.

```
                     (allowlist, DLC,                        (inter-arrival,          (50 trees,
                      rate limit)                             payload delta,           72 KB)

```

## Quickstart

```bash
pip install -r requirements.txt        # on Arch Linux ARM: use a venv (PEP 668)

# 1) the measured demo — works on any Linux/macOS host, no vcan, no sudo:
python 12_defense_demo.py --save results_poc.txt

# 2) rebuild the model on-board:
python 12_defense_demo.py --train

# 3) live on the Pi (real-time pacing, kernel RX timestamps):
sudo ./00_setup_vcan.sh
sudo python 12_defense_demo.py --mode live --save results_poc.txt
```

`smoke_test.py` is a fast end-to-end check that runs on python-can's
in-process bus (no vcan, no sudo): benign → masquerade hole → window-model
catch, printing the detector pair.

## Data and models

`data/` ships the labeled captures behind every number above (all generated by
`11_make_dataset.py`; regenerate with the three-terminal workflow in the file
headers):

- `raw_normal.csv` / `raw_attack.csv` — benign and attack-run frames
- `win_normal.csv` / `win_attack.csv` — 100 ms window feature tables

`model_window_drift.pkl` is the scored detector (trained: benign + masquerade
spikes + drift; shadow/replay/trojan held out as unseen classes).

Public datasets replay the same way (Task 1.2): the HCRL UAVCAN attack dataset
(arXiv:2212.09268) and OTIDS convert to candump logs via
`convert_dataset.py` / `pcap2log.py`, then `canplayer vcan0=can0 < log`.

## Honest boundaries

1. **Replay's coherent middle passes** (2/34 seam windows). Real bytes + real
   cadence defeat every current feature; the fix (payload-novelty /
   cross-sensor residual feature) is scheduled.
2. **Drift below the learned envelope passes** (boundary ≈ 1–2 m/s here);
   the threshold is the false-alarm operating point.
3. **Flood costs availability anyway** — rules stop the injection; only bus
   design bounds the denial (49 honest frames lost during the 1 s flood).
4. **The trojan is caught the moment it lies, never before** — nothing changes
   on the wire at takeover time; Tier 1 drops the OTA trigger, Tier 2 catches
   the behavior.
5. **vcan has no physical layer** (no arbitration delays / bit errors);
   message-level detection is the Phase-1 claim, wire-level work follows on
   the bench testbed.
